# Campus Exchange: UI/UX rescue

## Scenario and design decisions

A student needs to compare second-hand items, find something affordable and publish an item. The redesign gives these tasks concrete support:

- **Browse and assess:** consistent cards put title, numeric EGP price, condition, seller and pickup in the same place. Details retain the complete description and all existing photos. Sold items remain accessible through availability filters and My listings.
- **Find something affordable:** search, category filters, maximum budget, availability and both price sort directions work together. Results announce their count; empty states offer a filter reset. Available listings are shown by default.
- **Compare:** select up to three listings and compare price, condition, availability, pickup and seller in a semantic table. The comparison survives filter changes during the current visit. Selection is optional, never required to open an item.
- **Sell and manage:** the existing required fields remain. Errors explain how to fix each field and focus the first invalid input. A zero price is valid; negative, empty and non-finite prices are rejected. New items start active. Only owned listings expose edit or mark-sold actions, with ownership checked again when saving. My listings includes sold items and appears after a successful save.
- **Contact:** other active listings open a prefilled email draft. The UI explains this action before the user follows it. This standalone demo never sends a message itself.
- **Recover:** changes persist in localStorage under the original key. Storage failure is reported. Reset demo explains that it replaces local changes, and requires an explicit choice in the interface.

## Avoiding common mistakes in AI-generated interfaces

The following are design judgments applied to this project, informed by the sources below; they are not claims that a particular color or visual style is inherently generated by AI.

1. **A polished surface without task support.** A decorative landing page does not solve affordability or comparison. The marketplace includes functional budget filtering and a comparison flow, and all visible action controls have a concrete outcome.
2. **Generic patterns without context.** Student needs drive the information hierarchy: EGP prices, item condition and campus pickup are prominent. No invented ratings, verification badges, scarcity messages or usage statistics are added.
3. **Too many competing visual treatments.** The original purple and lavender palette, consistent line icons and a small typography hierarchy distinguish headings, content and actions. The book artwork is decorative and hidden from assistive technology.
4. **Weak errors and incomplete states.** Forms include labels, required indicators, field-specific instructions and success feedback. Empty results, missing photos, sold listings and unavailable browser storage each have a usable state.
5. **Accessibility added only at the end.** Native modal dialogs contain focus, close with Escape, make the page behind them inert and restore focus on close. Controls have visible focus states, comparison inputs have item-specific accessible names, status is communicated in text, and reduced-motion preferences are respected. Responsive layouts support narrow screens. This is not a formal WCAG certification.
6. **Misleading prototype behavior.** The interface identifies browser-only demo persistence and sample email behavior. Stock photos are retained as supplied; they are illustrative example records, not verified product photography. New listings use the existing no-photo fallback; photo upload is outside the README's functional brief.

## Research consulted

- [Nielsen Norman Group — Good from Afar, But Far from Good: AI Prototyping in Real Design Contexts](https://www.nngroup.com/articles/ai-prototyping/). Its evaluations describe the limits of generic AI patterns and the need for explicit context, design judgment and review. Applied here by designing around the student's browsing, budget, comparison and listing tasks.
- [W3C WAI — Forms Tutorial](https://www.w3.org/WAI/tutorials/forms/). Guidance on meaningful labels, instructions and accessible control structure.
- [W3C WAI — User Notifications](https://www.w3.org/WAI/tutorials/forms/notifications/). Guidance on clear, actionable error messages and success feedback, including feedback near the affected fields.
- [W3C WAI APG — Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). Guidance on focus containment, Escape dismissal, background interaction and focus restoration.

## Validation

Production build: `npm run build`.

Browser checks cover combined budget filters, comparison, empty required fields, rejection of negative prices, publishing with a price of zero, editing, marking sold and persistence across reload. Review also covers narrow-screen layout, email draft links, photo navigation, and resetting the disposable test listing.

This remains the standalone React demo specified in the README: no backend, authentication service or in-app messaging was added.
